# VPS deployment

Owner-requested planning for hosting the tracker on an existing Contabo VPS and enabling controlled assistance from AI agents. This group records proposed work; it does not authorize server changes, deployments or account mutations.

Read [the plan](plan.md), [agent access design](agent-access.md) and [Neon assessment](neon-assessment.md), then the existing [deployment requirements](../../docs/deployment.md), [production draft](../../deploy/README.md) and [hosted pilot gates](../../docs/pilot-readiness.md).

The owner reports a running VPS, root SSH access, an existing Neon Free account and no automatic VPS backups. OS, resources, region, domain and provider settings remain unverified. Keep host addresses, project identifiers, credentials and machine-specific configuration in private operator records.

The owner supplied a workspace-local `neon-setup.md`, outside Git. Its CLI linking/configuration recipe was reviewed as context; account identifiers are deliberately not copied here. It is not an application provisioning or compatibility test.

Use this group as one deployment plan with supporting design notes. Update checkboxes only after the stated evidence exists. Preserve lasting operations guidance in domain/runbook documentation and accepted database/access decisions in ADRs before retiring the plan.
